# Media Studio — image, audio and video system for any AI agent

One entry point. Any agent (Claude, Codex, Gemini, an API loop) reads this file, picks a route from the
requirement, and produces a finished file with the same contract every time.

Library root: `$AI_LIBRARY_ROOT` (default `vendor/library/`, filled by `scripts/setup.* --fetch-missing`)
Outputs: `$VIDEO_ROOT/projects/<YYYY-MM-DD>_<slug>/` — the [video-generations](https://github.com/Sanjayyykumar/video-generations) studio

## Why this is efficient
- **Code-first.** Anything that can be drawn in code (type, charts, diagrams, UI, illustration, motion
  graphics) is rendered from HTML/Canvas/React/Python, not generated by a diffusion model. It's exact,
  editable, cheap, and runs on any PC with no GPU.
- **AI only where code can't do it:** a real voice, photoreal imagery, live-action footage.
- **Stills before renders.** Render key frames first, check them, then encode. No wasted full renders.
- **One contract** (below), so engines are swappable and every job is resumable.

## Machine profile (example: a typical CPU-only laptop — run `python scripts/doctor.py` for yours)
- GPU: AMD Radeon integrated, ~2 GB shared. **No CUDA.** RAM ~10 GB.
- Installed: Python, Node, ffmpeg 9, uv.
- So: 2D code engines = fast. CPU TTS (Kokoro) = fine. Chatterbox / XTTS = slow on CPU (short clips only).
  Diffusion video (Wan, LTX, HunyuanVideo) and SDXL/Flux images = **not local**. Use a cloud route.

## Step 1 — Brief (always)
Write `brief.json` in the job folder:
```json
{ "goal": "", "audience": "", "format": "9:16 1080x1920 | 16:9 1920x1080 | 1:1",
  "length_s": 30, "language": "en | hi | hinglish", "style": "", "voice": "kokoro:<voice> | clone:<ref.wav> | none",
  "music": "pixabay | none", "sfx": true, "branding": { "handle": "", "end_card": true },
  "deliverables": ["mp4", "thumbnail.png", "srt"] }
```
Fill gaps with sensible defaults and state them; ask only if a wrong guess is expensive.

## Step 3 — Build (contract)
Job folder layout:
```
brief.json   script.md   storyboard.md (shots + timings)
assets/ (img, fonts)   audio/ (vo.wav, sfx/, music/, SOURCES.md)
src/ (engine code)     stills/ (one PNG per shot)   out/ (final.mp4, final.srt, thumbnail.png)
LOG.md (decisions, engine, render times, what to change next)
```
Order: script → voiceover (sets the timing) → shots timed to the VO → stills check → render → mix → QC.

## Step 4 — Mix (ffmpeg)
- VO -16 LUFS; music 18–22 dB under VO (sidechaincompress), fade in/out; SFX only on real events.
- Final: `loudnorm=I=-14:TP=-1.5`, AAC 192k, H.264 `-preset veryfast -crf 20 -pix_fmt yuv420p`.
- Subtitles: burn word-by-word for Reels, keep clear of bottom 300 px and right 120 px; also ship `.srt`.

## Step 5 — QC (never skip)
- Look at every still: nothing cut off, text readable at phone size, safe areas respected.
- `ffprobe` final: duration matches brief ±0.5 s, 30 fps, audio present.
- `ebur128` loudness check; no clipping (`astats` peak < -1 dBFS).
- SOURCES.md lists every third-party asset and its license.
